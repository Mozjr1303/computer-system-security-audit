02 · Methodology & Tools

Automated host inspection, backed by recorded OS evidence.

The WinSecAudit engine queried Windows internals directly through non-interactive PowerShell, WMI/CIM, Registry keys, and NTFS Access Control Lists. Every check was validated against CIS Microsoft Windows 11 benchmarks and scored transparently using a deterministic 100-point model.

1 · Environment

The audited host environment

One Windows 11 workstation, strictly local loopback queries, and standard Windows security interfaces.

In plain words

127.0.0.1 is the computer's loopback interface. The audit backend only talks to this computer itself; it cannot be reached from any Wi-Fi network or external website, and it does not make outbound network requests.

2 · Tools

Technologies and their roles

Every component has an explicit, modular responsibility in the auditing pipeline.

PowerShell 5.1 & WMI/CIM

OS Telemetry Layer

Primary telemetry collector.

Executes non-interactive cmdlets (Get-LocalUser, Win32_Service, Get-Acl, Get-MpComputerStatus) and streams structured JSON payloads back to the engine.

FastAPI & Python 3.11

Core Scoring Engine

Orchestration and validation.

Applies the 100-point scoring algorithm, enforces command safety policies, validates payloads with Pydantic v2 schemas, and serves 12 REST endpoints.

React 18 & Recharts

Analyst Dashboard

Interactive visual evaluation.

Provides radial posture gauges, category radar charts, filterable 31-check tables, and raw JSON telemetry inspectors for security analysts.

SQLite & ReportLab

Persistence & Reporting

Dossier generation.

Maintains historical audit scans in local SQLite storage and compiles formal multi-page PDF audit reports with color-coded severity badges.

3 · Process

The auditing process in seven stages

From initial privilege detection to persistence and formal PDF report compilation.

  1. 01 · Elevation & Context Check

    Detect OS build, hostname, architecture, and current process token (Standard User vs Administrator).

  2. 02 · User Account Enumeration

    Query local accounts, SIDs, Administrator group membership, password requirement flags, and password policies.

  3. 03 · Patch Currency Analysis

    Query installed KB hotfixes, days elapsed since latest patch, and Windows Update service configuration.

  4. 04 · NTFS ACL Inspection

    Retrieve Access Control Entries on 6 critical system directories and verify that standard users lack write rights.

  5. 05 · Service Binary Parsing

    Inspect all registered services for unquoted paths with spaces (CWE-428) and third-party LocalSystem services.

  6. 06 · OS Hardening Verification

    Audit Defender Antivirus, Real-Time Protection, 3 Firewall profiles, UAC Secure Desktop, and Secure Boot.

  7. 07 · Scoring & PDF Report

    Calculate 100-point posture score, store audit records in SQLite, and compile the formal assessment dossier.

4 · Engineering

A problem solved: safety & elevation boundaries

Guaranteeing non-destructive execution while handling elevation-gated Windows APIs gracefully.

Read-Only Command Safety Guard

To eliminate any chance of accidental modification, the PowerShell execution layer in powershell.py inspects every script block with a static regular-expression filter (FORBIDDEN_VERBS). Any command containing state-changing verbs such as Set-, Remove-, Stop-, Disable-, or New- is rejected immediately.

Elevation Handling (NOT_ASSESSED)

Certain low-level security APIs — such as querying BitLocker volume status (Get-BitLockerVolume) — require Administrator elevation and return Access Denied under a Standard User token. Instead of crashing or producing false failures, the engine marks these checks as NOT_ASSESSED and excludes them from the score denominator.

In plain words

If an auditor does not have administrative rights, they should not report that BitLocker is broken. They should accurately report "Not Assessed — Elevation Required" and grade the remaining 29 controls fairly.
